# JableLens 产品与数据源说明（给 Windows / Android 新版本开发用）

> 本文不依赖现有 Swift 代码，只描述「这个软件是什么、解决什么问题、数据从哪来、坑在哪」。
> 所有「已验证」的结论都来自 2026-10 在浏览器里的实际请求；标「未验证」的是推测。站点结构随时会变，开发时务必重新确认。
>
> 这是用户提供的原始说明（2026-10-23 存档）。Windows 版实测后发现的不同之处，见仓库根目录 README.md 的「实测记录」一节。

## 1. 背景与目标
- 用户个人自用的成人影片浏览 / 播放客户端，不存储、不转售影片，只是把几个公开网站的内容整合到一个干净、统一的界面。
- 已有 iPhone + Mac 版（Swift / SwiftUI）。现在要做 **Windows** 和 **Android** 版，需要重新实现，不复用原代码。
- 用户偏好：中文界面、简洁、像 YouTube 的信息结构（首页推荐、分类、搜索、详情、播放）、轻量不卡。
- 使用环境：用户在中国大陆以外或经代理访问这些站点（站点有 Cloudflare 防护，见 §4）。

## 2. 核心功能清单（原版已有，新版应对齐）
1. **首页 / 分类 / 搜索**：最新、热门、分类标签、关键词搜索、系列/厂牌目录。
2. **作品详情**：封面、标题、番号、演员、标签、发行日期、剧照轮播、简介；演员卡片可点进演员页。
3. **播放**：HLS（m3u8）播放，续播（记住进度）、倍速、双击快进快退、画中画（Android PiP / Windows 小窗）、隔空/投屏可选。
4. **演员资料与演员页**：生日、身高、三围、罩杯、作品列表；作品列表可按排序/年份/标签筛选；演员目录可按有码/无码、年龄段、身高、罩杯、胸围筛选并支持关键词搜索。
5. **关注演员 + 新作通知**：定期检查关注演员有没有新作，推送通知，点通知直接进入该作品。
6. **继续观看 / 历史 / 收藏**。
7. **下载**（把 HLS 转成本地文件，可选，优先级低）。
8. **桌面小组件**（iOS 独有，Android 可对应 App Widget）：显示继续观看/最新作品封面。
9. **MissAV 目录**：含「亚洲 AV」系列（麻豆传媒、TWAV、Furuke、韩国直播、中国直播）的快捷入口。
10. **字幕**：播放时按番号去字幕站搜索 .srt，叠加在画面上，可切换语言、开关、整体对时（整体平移）。
11. **演员名自动对应**：不同站点对同一演员的写法不同（见 §5），需要自动映射。

## 3. 数据来源总览
| 来源 | 角色 | 访问方式 | 稳定性 |
|---|---|---|---|
| **Jable**（jable.tv） | 唯一播放源、列表、搜索 | 网页（有 Cloudflare 挑战） | 需要真实浏览器环境 |
| **MissAV**（missav.ws） | 另一个目录与播放源 | 网页（有 Cloudflare） | 同上 |
| **AV01**（www.av01.media） | 作品 JSON 数据、演员名（日文 + 简繁译名） | 直接 HTTP JSON | 较稳 |
| **Netflav**（netflav.com） | 剧照、演员资料、演员作品列表、演员目录 | JSON 接口 + 网页内嵌 JSON | 接口不全，见 §5 |
| **subtitlecat.com** | 字幕 | HTML 页面 + .srt 下载 | 内容质量不稳定 |
| **R18.dev**（r18.dev） | 官方资料补充：日文原题、厂牌、导演、片长、分类、演员日文名、DMM 封面/剧照地址 | 公开 JSON，无需登录 | 已验证可用（见 §7b） |

原则：**播放永远走 Jable（或 MissAV 目录里的片子走 MissAV）；Netflav / AV01 只提供元数据。**

## 4. Cloudflare 与「网页读取」问题（最大的工程难点）
- Jable、MissAV 会对非浏览器客户端触发 Cloudflare 挑战，直接 HTTP 请求通常被拦。
- 原 iOS 版的做法：用 **WKWebView（真实浏览器内核）** 打开页面，等页面渲染完成后用 JS 读 DOM / 读取页面里的数据，遇到挑战页面时让用户在内嵌网页里手动通过验证，通过后复用 cookie。
- 新版对应方案：
  - **Android**：`WebView`（同样的思路：加载页面 → 等就绪 → `evaluateJavascript` 读取）。
  - **Windows**：`WebView2`（Edge 内核）。
  - 不要尝试绕过 / 破解 Cloudflare；让真实浏览器内核通过，并保存会话 cookie。
- 优化经验：不要等页面完全加载；轮询「目标元素已出现」就提前返回，并停止加载（原版「readEarly」，轮询约 200ms，总超时约 35 秒）。
- 播放地址：详情页里能拿到 m3u8（HLS）地址，播放器请求视频分片时需要带 **Referer**（Jable：`https://jable.tv/`；MissAV 封面域名 fourhoi.com 需要 Referer `https://missav.ws/`）。

## 5. Netflav 接口细节（已验证，2026-10）
请求头需带 `client: client`（部分接口）。

- **演员目录（可筛选）**：`GET https://netflav.com/api98/actress/getActress?page=<n>&type=<censored|uncensored>&age=<1-6>&height=<1-6>&breast=<1-11>&waist=&hip=&cup=<A-M,O>`
  - age：2=超年輕 … 6=四十路；height：1=<160 … 6=180+；breast：1=<28，2=28 … 10=44，11=44+。
- **演员搜索**：`GET /api98/actress/searchActress?page=<n>&keyword=<名>`，返回 `_id,type,icon,name,name_en,videoCount`，**不含生日/身高等资料**。
- **作品搜索**：`GET /api98/video/advanceSearchVideo?type=title|actress|actor|tag|genre&page=<n>&keyword=<词>`。
  - ⚠️ **`type=actress` 是模糊匹配，结果会混入别的演员的作品**（例：搜「和香なつき」得到 99 条，前 8 条全是别人的作品，真正的 MFYD-202 不在其中）。**不要用它当「演员作品列表」。**
- **演员作品列表（推荐）**：取网页 `https://netflav.com/all?actress=<名>&page=<n>`，HTML 里的 `<script id="__NEXT_DATA__">` → `props.initialState.all`：
  - `docs`（每页 20 条）、`page`、`pages`、`total`；`total/pages` 会漂移，**以「docs 为空就结束」为准**。
  - 每条作品：`code / uCode`（番号）、`title / title_zh / title_en`、`actors`（形如 `["jp:和香なつき","和香なつき","zh:...","en:..."]`）、`tags`、`sourceDate`（发行日期，ISO，`videoDate` 常为空）、`preview` 等。
  - 演员资料在同一个 JSON 里：`initialState.all.actress`（`birthday, height, cup, breast, waist, hip, videoCount, name, name_ja, name_zh`）；⚠️ **部分演员没有 actress 对象**（Netflav 就是没收录），界面应显示「Netflav 没有该演员资料」，不要报错。
  - 用站点不认识的写法查（例如汉字写法「和香奈月」）会得到**空列表**，必须先换成 Netflav 的名字。
- **番号搜作品**：`advanceSearchVideo?type=title&keyword=MFYD-202`，返回该作品的 `actors`（可用来反查 Netflav 上的演员名）。

### 演员名对应（两个站点写法不同）
- Jable 用中文/汉字名（例：和香奈月），Netflav 用日文原名（例：和香なつき），AV01 同时给日文名 + 简/繁/港译名。
- 对应策略（原版已实现，新版需重做）：
  1. 候选名：原名 + 简繁互转；
  2. 用 Netflav 演员搜索：精确匹配或唯一结果即采用（要考虑括号别名）；
  3. 用 AV01 的「番号 → 演员」配对；
  4. 用 Netflav 的「番号 → actors」按相似度（≥0.5）匹配；
  5. 结果缓存（本地持久化），详情页演员显示优先用 Netflav 的写法，没有再退回 Jable。
- 简繁转换：Android 可用 ICU `Transliterator`（`Hans-Hant` / `Hant-Hans`）；Windows 可用 OpenCC 或自带词表。

## 6. MissAV 细节（已验证）
- 列表：`https://missav.ws/cn/<路径>?page=N`；卡片 `div.thumbnail`，标题 `a.text-secondary`，封面 `img[data-src]`（来自 fourhoi.com，需 Referer `https://missav.ws/`）。
- 亚洲 AV 系列路径：`madou`（麻豆）、`twav`、`furuke`、`klive`（韩国直播）、`clive`（中国直播）；直播类番号形如 `KBJ-25022770`、`CN-25022507`。
- MissAV 的演员页没有生日/身高等资料。

## 7. 字幕（subtitlecat.com，已验证）
- 搜索：`GET https://www.subtitlecat.com/index.php?search=<番号>` → 结果表格里每行 `<a href="subs/<id>/<名>.html">标题</a>`；标题里含番号才算匹配（压缩成字母数字后比较）。
- 字幕页：每种语言一行：`<img src="/assets/flags/xx.png" alt="<语言码>" class="flag"></span><span><语言名></span><span><a id="download_<语言码>" ... href="/subs/<id>/<文件名>-<语言码>.srt">`；href 里含空格与括号，需做 URL 编码（若已含 `%` 则不要重复编码）。
- 实测 MFYD-202 有简体中文、繁体中文、English 等 13 种（多为机翻再翻译，质量不稳定）。
- .srt 解析要点：去掉 UTF-8 BOM、统一换行、按空行分块、时间 `HH:MM:SS,mmm --> HH:MM:SS,mmm`、去 `<...>` 与 `{\an8}` 标签、过滤广告行（如含 `transub.cc`）。
- **对时是核心问题**：字幕往往按别的视频版本制作，开头偏差可达几秒到几十秒，所以必须提供：
  - 「把当前播放位置对准第一句台词」（用户听到第一句话时点一下，计算偏移 = 当前时间 − 字幕第一句开始时间）；
  - ±1 秒、±10 秒微调；
  - 偏移按番号持久化。
  - 只靠整体平移解决不了帧率不一致造成的逐渐漂移，这种情况应换另一条字幕轨道。
- 字幕是应用自己叠加渲染的（不是视频内嵌），画中画窗口里不会显示。

## 7b. 元数据补充来源（R18.dev 与其它，2026-10 核对）
用户参考的 Peach 项目（https://demo.peach.video/sources）列了很多「元数据来源」，**它们只提供资料/封面，不能播放**。分类与结论：

**已验证、已接入 iPhone 版：R18.dev**
- 接口：`GET https://r18.dev/videos/vod/movies/detail/-/combined=<content_id>/json`（无需登录）。
- 已确认的字段：`content_id, dvd_id(常为 null), title_ja, title_en(机翻), release_date, runtime_mins, maker_name_ja/en, label_name_ja/en, series_id, jacket_full_url, jacket_thumb_url, sample_url, gallery[]`，以及 `actresses[]{id,name_kanji,name_kana,name_romaji}`、`directors[]{id,name_kanji,...}`、`categories[]{id,name_ja,name_en}`。
- **番号 → content_id 要自己推**（DMM 的编号）：新片是「小写前缀 + 5 位补零数字」，如 MFYD-202 → `mfyd00202`；旧片常是不补零，如 PRED-749 → `pred749`（封面在 `pics.dmm.co.jp/mono/movie/adult/pred749/pred749pl.jpg`，而新片在 `.../digital/video/mfyd00202/mfyd00202pl.jpg`）。部分厂牌还有数字前缀（如 `1xxx`、`h_xxxx`），**推不出来就当没有资料**。
- ⚠️ 用 `dvd_id=<番号>` 查在一次抽查中返回了别的作品（MFYD-202 → content_id `mfyd00022`），**不要依赖 dvd_id 查询**；只用 `combined=<content_id>`。
- 防张冠李戴：**只有 `release_date` 与本地已知的发行日完全一致才采用**，否则丢弃。
- 拿到的日文演员名（`name_kanji`）还可以用作 §5「演员名对应」的额外候选（原版尚未接入）。
- 封面/剧照：DMM 图片域名 `pics.dmm.co.jp`，无需 Referer；`pl.jpg` 是**宽幅封面（含封底）**，直接放进 16:9 会带封底，要裁右侧约 72% 才是正面。
- 国内网络环境下 r18.dev / DMM 是否可直连：未验证。

**未验证 / 不建议**
- **みんなのAV（minnano-av.com）**：演员资料最全，但在测试浏览器里被 **Cloudflare 人机验证**拦住，只能走 WebView 读取路径；未验证能否稳定读到生日/身高/三围。
- **AVBase（avbase.net）**：无需登录，作品页能按番号找到演员；演员页路径 `https://www.avbase.net/talents/<URL 编码的名字>`；但测试的演员（和香なつき）「プロフィール」栏是**空的**，所以不能保证补到身高三围。
- **JavDB / JavBus / FC2 系列**：需要登录 Cookie 或人机验证，不建议。
- **sukebei 等种子索引、amane 之类下载/解析组件**：不接入。
- 其余（Prestige、MGStage、FALENO、DAHLIA、一本道、片商官网）：只有片商自己的作品，逐个解析成本高，收益小。
- 想补全「Netflav 没有的演员资料」：优先试 minnano-av（经 WebView），其次 AVBase；做之前必须先实测页面结构。

## 8. 关注与新作通知
- 用户关注演员后，App 定期（后台）检查该演员的新作（以演员作品列表的最新条目对比已知番号），有新作发本地通知，点通知直达该作品详情。
- 平台约束：Android 用 WorkManager 周期任务（最短 15 分钟）；Windows 用后台任务/托盘常驻。
- 通知带番号 `code`，点击回调里打开作品。

## 9. 数据模型（建议）
- **Video**：id、番号、标题、封面 URL、发行日期、演员[]、标签[]、播放页 URL、来源（Jable/MissAV/AV01/Netflav）。
- **CodedWork**（按番号的作品，来自 Netflav 演员页）：番号、标题、封面、日期、标签[]。
- **PerformerProfile**：名字、生日、身高、罩杯、胸/腰/臀围；`age` 由生日算出。
- **PerformerQuery**（目录筛选）：类型（有码/无码）、年龄档、身高档、胸围档、罩杯、关键词。
- **SubtitleTrack**：语言码、显示名、来源标签、URL；**SubtitleCue**：开始、结束、文本。
- 本地持久化：关注演员、观看进度/历史、收藏、演员别名缓存、字幕偏好（是否开启、语言、按番号的偏移）。

## 10. 已知问题与注意事项
- 站点结构会变；任何一个解析点都要有「读不到时的清楚提示」，不要整页崩溃。
- 用户反馈过「卡卡的」和「MissAV 加载有问题」，但没给出具体页面/报错，**原因未知**；新版从一开始就要做列表虚拟化/图片缓存/分页加载，并避免在主线程做网络、数据库、密钥读取等同步 I/O（原版曾怀疑主线程钥匙串读取导致卡死）。
- 封面图尺寸不一（有宽图有竖图）；小组件/网格里统一裁成同一比例（原版：宽图取右侧约 72% 宽度，再居中裁成 4:5），否则排版很乱。
- 通知点击在原 iOS 版曾崩溃（异步回调写法问题），新版要在点击回调里把「打开哪个番号」交给主界面，不要在回调里做重活。
- 隐私：不要把用户的账号、cookie、观看记录发送到任何第三方；这些站点 / 字幕站的主机用白名单限制。
- 内容性质：这是成人内容，应用本身应有年龄提示，不上架公开商店的话只作个人/侧载使用。

## 11. 明确不做
- 不接入 aiyeyu.com（用户曾两次提出，已决定不做，不要再加）。
- 不绕过 Cloudflare / 付费墙。

## 12. 建议的开发顺序
1. **先做数据层并在命令行/单元测试里验证**：Netflav 演员页 JSON、AV01 JSON、字幕搜索与 .srt 解析、名字对应、简繁转换。
2. 再做 Jable/MissAV 的 WebView 读取（最脆弱，要有挑战页处理）。
3. 播放器（HLS + Referer + 续播 + 倍速）+ 字幕叠加与对时。
4. 列表/详情/演员页界面，接着是关注与新作通知。
5. 最后：下载、小组件、封面墙（想做的新功能，见下）。

## 13. 想做但还没做的新功能（来自 Peach 项目启发）
- **封面墙**：纯封面瀑布流浏览模式（最容易，数据已有）。
- **创作者/新作订阅**：在「关注演员」基础上扩展订阅类型。
- **在线字幕增强**：更多字幕来源、字幕质量标记、自动对时（根据音频/片头判断偏移，难度大）。
- 参考项目：https://github.com/peach-mitao/peach（自托管的 Python/React/Docker 媒体库，AGPL-3.0）；只读过它的 README，**没读过源码**，若要借鉴其思路再去读。

## 14. 与用户协作的约定
- 用中文回复，简洁，用人话；
- 对没验证的东西老实说「没验证」，不要把推测说成事实；
- 用户反馈含糊时，先问具体页面、操作、报错文字，不要猜；
- 完成一块功能后给用户一个清楚的「怎么试、预期看到什么」。
